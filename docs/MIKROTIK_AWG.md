# MikroTik: BGP и AmneziaWG-контейнер

Эта инструкция описывает три варианта: только BGP, BGP с готовым подключением Amnezia и BGP с собственным сервером Amnezia. Последние два варианта используют **AmneziaWG внутри контейнера**, не стандартный WireGuard RouterOS.

Проверенный рабочий стенд: RouterOS **7.24.4** на ARM (RB3011), пакет `container` той же версии, контейнер [catesin `Containers_3.1`](https://github.com/catesin/AmneziaWG-MikroTik/releases/tag/Containers_3.1) на внешнем ext4-накопителе, клиентский профиль AWG 2.0, BGP от отдельной Linux VM. Проверены запуск туннеля, handshake, передача трафика, BGP-маршруты и восстановление после перезагрузки. **Чистая установка на другом роутере ещё не проверена.** Другие архитектуры и версии RouterOS сначала проверяйте отдельно. Контейнер является сторонним проектом, а не официальным клиентом Amnezia.

> [!WARNING]
> Маршрутизация, firewall, BGP и Containers могут прервать доступ к сети. Создайте зашифрованный backup RouterOS и текстовый export **локально**, скачайте их с роутера и проверьте аварийный доступ через MAC WinBox или консоль. Не публикуйте конфигурацию AWG, private key, endpoint и полный export. Если нет опыта с MikroTik, попросите сетевого специалиста помочь с изменениями. Всё выполняется на ваш риск.

## 1. Выберите вариант

| Вариант | Что требуется |
|---|---|
| Только BGP | RouterOS 7, работающий egress gateway для полученных маршрутов; контейнер не нужен. |
| BGP + готовый Amnezia VPN | Совместимый RouterOS, пакет и режим Containers, внешний диск, отдельный клиентский конфиг AmneziaWG. |
| BGP + свой сервер | Всё из предыдущей строки и свой работающий AmneziaWG-сервер. |

RouterOS 6 **не поддерживает Containers** и не подходит для контейнерных вариантов. Помощник **Для MikroTik** выдаёт команды BGP только для RouterOS 7: не запускайте их на RouterOS 6. Для RouterOS 6 нужна отдельная ручная настройка BGP специалистом; эта инструкция её не проверяет. В варианте «только BGP» полученные адреса имеют смысл лишь при доступном следующем хопе: без VPN или иного маршрутизатора трафик может стать недоступным.

## 2. Подготовка роутера и VPN

1. В портале **Для MikroTik** выполните предложенные команды только для чтения. Проверьте архитектуру и версию RouterOS. Пакет `container` должен иметь ту же версию, что `routeros`, а `container` в `/system/device-mode/print` должен быть `yes`. Включение режима Containers требует физического доступа и перезагрузки; следуйте [официальной инструкции MikroTik](https://manual.mikrotik.com/docs/containers/).
2. Проверьте внешний накопитель: `/disk/print detail`. Он должен быть смонтирован **rw**, иметь файловую систему ext4/btrfs и достаточный запас места. Если форматирование вызывает ошибки, тайм-ауты или перезагрузку роутера, **остановитесь и замените накопитель**. Не размещайте рабочий контейнер на встроенной flash-памяти, если есть внешний диск: это также [рекомендация MikroTik](https://manual.mikrotik.com/docs/containers/).
3. Создайте отдельного клиента в Amnezia, проверьте его на телефоне или ПК и экспортируйте **нативный конфиг AmneziaWG**. Нужен именно клиентский конфиг AWG, не ссылка-приглашение и не обычный WireGuard. Для собственного сервера следуйте [официальной инструкции Amnezia](https://docs.amnezia.org/documentation/instructions/install-vpn-on-server/). Не обновляйте существующий AWG 2.0 сервер до 3.1 только ради этой инструкции: [официальная миграция](https://docs.amnezia.org/documentation/instructions/new-amneziawg-selfhosted/) удаляет старых пользователей. Контейнер 3.1 на проверенном стенде успешно подключается с профилем AWG 2.0; сервер AWG 3.1 здесь не проверен.
4. Скачайте подходящий вашей архитектуре **tar из конкретного релиза** `Containers_3.1`; не используйте плавающий `latest`. Для ARM файл `awg-mikrotik-arm-Containers_3.1.tar` на проверенном стенде имел SHA-256 `65eddd9d858fa82da11544a6c3ff0321373540a14487331a190ca1b7bd5eef73`. Сравните хеш до загрузки в MikroTik. Для arm64/x86 не подставляйте этот ARM-хеш: он к ним не относится.

> [!NOTE]
> The333-BGP не получает VPN-конфиг и не управляет VPN-ключами. Файл `awg0.conf` остаётся на вашем роутере/накопителе. Не вставляйте его в портал или GitHub Issue.

## 3. Сначала запустите контейнер без BGP

Ниже пример **для чистой конфигурации** с отдельной подсетью `172.18.20.0/30` и внешним диском `usb1`. Сначала проверьте, что эта подсеть, имена и адреса не заняты. Если уже есть рабочий veth, таблица или контейнер, **не запускайте блок поверх них**: сверяйте существующие объекты и сохраняйте свою топологию. Команды изменения выполняйте в Safe Mode из одной сессии; промежуточные проверки делайте до выхода из него.

Создайте veth и адрес RouterOS, затем каталоги конфигурации и распаковки:

```routeros
/interface/veth/add name=the333-awg-veth address=172.18.20.2/30 gateway=172.18.20.1
/ip/address/add address=172.18.20.1/30 interface=the333-awg-veth
/file/add name=usb1/the333-awg-conf type=directory
/file/add name=usb1/the333-awg-tmp type=directory
/container/config/set tmpdir=usb1/the333-awg-tmp
/container/mounts/add list=the333-awg-conf src=usb1/the333-awg-conf dst=/etc/amnezia/amneziawg
```

В клиентском `awg0.conf` оставьте **ровно один** файл `*.conf` в смонтированном каталоге: контейнер может попытаться поднять каждую найденную конфигурацию. Настройте `AllowedIPs = 0.0.0.0/1, 128.0.0.0/1` для полного IPv4-трафика контейнера через AWG и два hook-поля в `[Interface]`, направляющие **публичный IP VPN endpoint** обратно через `172.18.20.1` и veth. Подставьте реальный IP endpoint вместо `VPN_SERVER_IPV4`; DNS-имя здесь может сломать маршрут до его разрешения. Не копируйте этот фрагмент как полный конфиг: ключи и параметры AWG остаются из собственного экспорта Amnezia.

```ini
# Добавить внутри [Interface], перед [Peer]:
PreUp = ip route add VPN_SERVER_IPV4/32 via 172.18.20.1 dev the333-awg-veth
PostDown = ip route del VPN_SERVER_IPV4/32 via 172.18.20.1 dev the333-awg-veth

# В существующем [Peer] изменить:
AllowedIPs = 0.0.0.0/1, 128.0.0.0/1
Endpoint = VPN_SERVER_IPV4:VPN_SERVER_PORT
```

Загрузите конфиг в `usb1/the333-awg-conf/awg0.conf`, а tar-образ в корень `usb1` через WinBox Files. Не храните вторую `.conf` рядом, даже с суффиксом `-old.conf`. Создайте контейнер **с выключенным автозапуском**; `root-dir` заранее не создавайте. Для ARM:

```routeros
/container/add name=amneziawg-client file=usb1/awg-mikrotik-arm-Containers_3.1.tar interface=the333-awg-veth mountlists=the333-awg-conf root-dir=usb1/the333-awg-root hostname=amneziawg logging=yes start-on-boot=no
/container/print detail where name="amneziawg-client"
```

Дождитесь окончания распаковки. Для arm64/x86 измените **только имя проверенного tar нужной архитектуры**. Затем запустите и проверьте туннель:

```routeros
/container/start [find where name="amneziawg-client"]
/container/print detail where name="amneziawg-client"
/container/shell [find where name="amneziawg-client"]
```

В консоли контейнера:

```sh
chmod 600 /etc/amnezia/amneziawg/awg0.conf
awg show awg0 latest-handshakes
ping -c 3 -I awg0 1.1.1.1
awg show awg0 transfer
exit
```

Нужны свежий handshake, успешный ping и растущие счётчики transfer. Если их нет, **BGP не включайте**. Проверьте ключ/endpoint/порт/AllowedIPs/hooks и время на роутере. После успешной проверки разрешите автозапуск:

```routeros
/container/set [find where name="amneziawg-client"] start-on-boot=yes
```

## 4. Дополнительно: маршруты из списка `to_vpn`

**Для маршрутов, полученных от The333-BGP, этот раздел не обязателен.** Помощник настраивает их входной BGP-фильтр с `set gw 172.18.20.2` в таблице `main`. Таблица `r_to_vpn` и правила mangle нужны лишь тогда, когда вы **дополнительно** направляете через AWG адреса из собственного списка `to_vpn` или другой policy-routing трафик. Не добавляйте их ради работы одного только BGP.

Сначала проверьте существующие правила FastTrack, mangle и NAT в WinBox. FastTrack может обходить policy routing; его исключение для помеченных соединений зависит от вашего firewall. **Не отключайте весь FastTrack вслепую.** Если не знаете, как безопасно исключить VPN-трафик, обратитесь к специалисту.

В чистой схеме создайте отдельную FIB-таблицу и маршрут через veth. **Не добавляйте default route в `main`.** До применения убедитесь, что подсеть veth не пересекается с локальными сетями:

```routeros
/routing/table/add name=r_to_vpn fib
/ip/route/add dst-address=0.0.0.0/0 gateway=172.18.20.2%the333-awg-veth routing-table=r_to_vpn comment="the333: AWG table default"
/ip/firewall/nat/add chain=srcnat action=masquerade out-interface=the333-awg-veth comment="the333: AWG veth NAT"
```

Правила mangle зависят от действующего firewall. Для нового роутера сначала создайте исключение своих локальных подсетей, затем **только после проверки порядка правил** добавьте маркировку назначения `to_vpn` и отправку в `r_to_vpn`. Это не универсальный блок для слепой вставки: порядок относительно существующих FastTrack, PCC, NAT, VLAN и policy routing должен проверить человек. Рекомендуемый порядок и параметры показаны в [проекте проверенного стороннего контейнера](https://github.com/catesin/AmneziaWG-MikroTik#преднастройка-routeros). Перед включением BGP проверьте тестовый адрес в `to_vpn`, счётчики mangle/NAT, маршрут в `r_to_vpn` и фактический выход клиента через VPN.

## 5. Подключите The333-BGP

Откройте вкладку **Для MikroTik** портала. Выполните read-only preflight, затем выберите **BGP + AWG-контейнер**, задайте gateway `172.18.20.2` и Community, совпадающее с публикацией на VM. Сначала выполните **Подготовить в карантине**; BGP остаётся выключенным. Проверьте созданные instance, connection и фильтр. Только после успешной проверки скопируйте команду активации. В BGP input filter должно быть `set gw 172.18.20.2` **только для подходящих IPv4-маршрутов** и завершающий `reject`; RFC1918/служебные сети должны отклоняться.

После активации проверьте `state=established`, число принятых маршрутов, один конкретный маршрут и реальный клиентский запрос через VPN. `Established` без проверенного выхода через AWG **не доказывает** рабочую схему. Проверьте весь путь после перезагрузки роутера: диск смонтирован rw, контейнер RUNNING, handshake свежий, BGP-сессия established и выбранные адреса проходят.

## Откат и частые ошибки

- **Срочно убрать BGP-маршруты:** выключите созданное BGP connection или выполните блок **Rollback** в помощнике. Не удаляйте контейнер и routing rules во время аварийного отката: сначала верните доступ.
- **Туннель перестал отвечать:** оставьте BGP выключенным до свежего handshake и проверки выхода. Старые принятые маршруты не должны оставаться основанием для предположения, что VPN работает.
- **Нет `awg0`:** проверьте путь mount, имя `awg0.conf`, права `600`, отсутствие других `*.conf` и логи контейнера.
- **После reboot контейнер STOPPED:** проверьте USB, `start-on-boot=yes` и логи RouterOS. Ошибки файловой системы/перезагрузки при форматировании означают проблему с накопителем, а не повод повторять команды.
- **BGP established, трафик мимо VPN:** для BGP-маршрута проверьте Community, `set gw`, NAT и фактический gateway выбранного адреса; для дополнительных адресов из `to_vpn` также проверьте таблицу `r_to_vpn` и порядок mangle/FastTrack.

Для очистки тестовой установки удаляйте **только объекты, которые создали сами**, сверив имена и backup. Не запускайте общий `remove [find]` по чужим правилам. Штатное обновление The333-BGP на Linux VM не обновляет RouterOS, этот контейнер или ваш Amnezia-сервер.
